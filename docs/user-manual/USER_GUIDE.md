# دليل المستخدم — ELTARANISI ERP
## (للمحاسب، ومدير الشركة، والمدير المالي)

---

## 1. الدخول إلى النظام

1. افتح `http://localhost:8000`.
2. اكتب **اسم المستخدم** و**كلمة المرور** (من `data/dev-credentials.txt` في بيئة التطوير).
3. لإظهار كلمة المرور اضغط أيقونة العين.
4. زر **AR / EN** أعلى الشاشة يبدّل اللغة والاتجاه (RTL ⇄ LTR) بدون إعادة تحميل.
5. زر القمر/الشمس يبدّل الوضع الليلي. النظام يتذكّر اختيارك.

> إذا ظهر «اسم المستخدم أو كلمة المرور غير صحيحة» بعد 8 محاولات، الحساب مقفول 15 دقيقة.

---

## 2. الشاشة الرئيسية (لوحة المعلومات)

- **بطاقات المؤشرات**: الإيرادات، المصروفات، صافي الربح، السيولة النقدية،
  **إجمالي مديونية الموردين**، **المتأخر منها**، مستحقات العملاء، قيمة المخزون.
- **الرسم البياني**: الإيرادات مقابل المصروفات لآخر 6 أشهر.
- **أرصدة البنوك والصناديق**.
- **أعلى الموردين مديونية** + تاريخ أقرب استحقاق.
- **أعمار الديون** (مدينة ودائنة).
- **الإجراءات السريعة**: قيد جديد · فاتورة بيع · سند قبض.

كل الأرقام من القيود المرحّلة فقط. لا مسودات، ولا أرقام تقديرية.

---

## 3. القيود اليومية (دورة القيد)

### إنشاء قيد
1. **القيود اليومية** ← «قيد جديد».
2. اختر التاريخ، النوع (يدوي/افتتاحي/تسوية/مصروف…)، واكتب البيان.
3. أضف السطور: الحساب + مدين أو دائن + الوصف.
4. الميزان أسفل النموذج يجب أن يكون **متوازنًا** (أخضر). إذا كان أحمر لا يُحفظ.
5. **حفظ كمسودة** ← يظهر رقم القيد (`JE-2026-xxxxx`).

### المراجعة والترحيل
| الحالة | من يتحرك | ماذا يفعل |
|---|---|---|
| مسودة | المُنشئ | يرسل للمراجعة زر «إرسال للمراجعة» |
| مراجعة | رئيس الحسابات / المدير المالي | يعتمد أو يرفض بسبب مكتوب |
| معتمد | صاحب صلاحية الترحيل | «ترحيل» ← القيد يُؤثر في الأرصدة |
| مرحّل | — | **لا تعديل**؛ التصحيح بقيد عكسي |

> **قاعدة مهمة**: لا يمكنك اعتماد قيد أنت منشئه (فصل مهام). يحتاج قيد ثانٍ بشري.
> القيود ≥ **200,000 ج.م** تحتاج اعتماد المدير المالي.

### عكس قيد
افتح القيد المرحّل ← «عكس القيد» ← اكتب السبب. يُنشأ قيد عكسي مرحّل بقيم متساوية، ويبقى الأصل
في السجلات للمراجعة.

### استيراد CSV
«استيراد القيود» ← اختر الملف ← يتحقق النظام من التوازن والحسابات والفترات ويُظهر الأخطاء سطرًا بسطر
قبل أي ترحيل.

## 4. الفواتير

### فاتورة بيع
1. **المبيعات** ← «فاتورة جديدة».
2. اختر العميل (يظهر رصيده وحد ائتمانه)، المستودع، التاريخ وتاريخ الاستحقاق.
3. أضف الأصناف: الكمية، السعر، الخصم، نسبة الضريبة.
4. **حفظ كمسودة** ثم **ترحيل**، أو ضع علامة «ترحيل فوري».
5. عند الترحيل يتأثر: حساب العميل (مدين)، الإيرادات (دائن)، ضريبة المبيعات (دائن)،
   المخزون وتكلفة المبيعات تلقائيًا.

### فاتورة شراء
نفس الخطوات: المورد، المستودع، الأصناف، ثم الترحيل ← يزيد المخزون ويظهر التزام على المورد.
لا تُقبل فاتورة بنفس رقم مرجع المورد مرتين.

### سند قبض / صرف
- **سند قبض**: العميل + المبلغ + الحساب البنكي/الصندوق + تخصيص المبلغ على الفواتير.
- **سند صرف**: المورد أو حساب المصروف + الحساب البنكي/الصندوق.
- لا يمكن تخصيص أكثر من رصيد الفاتورة المتبقي — يظهر خطأ `OVER_ALLOCATION` بوضوح.

## 5. مديونية الموردين (أهم تقرير للمدير المالي)

**المشتريات → مديونية الموردين**:
- إجمالي المديونية، المدفوع، المتبقي، المتأخر، أقرب استحقاق каждой فاتورة.
- أعمار الديون في 5 نطاقات.
- عمود **«رصيد الأستاذ»** يجب أن يطابق المتبقي — إن اختلفا فهناك مشكلة تستحق الفحص.
- تصدير CSV، أو طباعة PDF من المتصفح.

## 6. التقارير

كل تقرير يقبل **الفترة + الفرع + المركز**، ويُصدَّر CSV/Excel وطباعة PDF.

| التقرير | الاستخدام |
|---|---|
| ميزان المراجعة (ملخص/تفصيلي) | التحقق من توازن الحسابات |
| قائمة الدخل | الأرباح والخسائر للفترة |
| المركز المالي | الأصول = الالتزامات + حقوق الملكية |
| التدفقات النقدية | حركة البنوك والصناديق |
| أعمار الديون | متأخرات العملاء والموردين |
| الأستاذ العام | حركة حساب معين بتفصيل |
| موازنة مقابل الفعلي | الانحرافات وتجاوز الموازنة |

> إن أظهر ميزان المراجعة فرقًا غير صفري، **لا تُرحّل أي شيء**؛ أبلغ المحاسب المسؤول.

## 8. المساعد المالي

اسأله بلغة عادية، مثل:
- «إجمالي مديونية الموردين والمتأخر منها؟»
- «صافي ربح هذا الشهر؟»
- «كم رصيد البنك؟»

يعرض **مصدر الأرقام** ويقول صراحةً إنه من القيود المرحّلة. **لا ينفذ أي عملية**: لا يرحّل ولا يدفع
ولا يحذف، ولا يرى إلا ما تسمح به صلاحياتك. والتوقعات (إن طلبتها) تُعرض كتقديرات احتمالية.

## 10. تصدير المستندات وإعدادات الشركة (جديد)

### تصدير فاتورة
افتح الفاتورة ← أعلى الصفحة زر **📄 PDF / طباعة**:
- **معاينة وطباعة** — يعرض نفس ملف PDF داخليًا مع إمكانية الطباعة.
- **تنزيل PDF عربي / إنجليزي** — نفس الفاتورة بلغة مختلفة (الخط العربي مضمَّن داخل الملف).
- **Excel** — نسخة RTL قابلة للتحرير.
- **فاتورة إلكترونية** — بيانات JSON جاهزة مع UUID وبصمة SHA-256 (غير موقّعة) وزر نسخ.

> كل تنزيل يمرّ عبر جلسة المستخدم ويُسجَّل في سجل التدقيق باسمك — لا روابط عامة قابلة للتخمين.

### تصدير تقرير
في أي تقرير (ميزان المراجعة، قائمة الدخل، المركز المالي، التدفقات، أعمار الديون، مديونية الموردين)
اضغط **⬇ تصدير** واختر: PDF عربي · PDF إنجليزي · Excel (RTL) · CSV. الفلاتر المطبّقة على الشاشة
(من/إلى تاريخ) تنتقل نفسها إلى الملف.

### إعدادات الشركة
**إعدادات الشركة** في القائمة الجانبية (لمن يملك صلاحية `settings.manage`): الاسم العربي/الإنجليزي،
الرقم الضريبي، الهاتف، العنوان، البريد، الموقع، بيانات البنك، شروط السداد، وتذييل الفاتورة — مع
**معاينة حيّة** لرأس الفاتورة. ما تكتبه هنا يُطبع فورًا على كل PDF/Excel جديد.

## 11. حذف سجل أُنشئ بالخطأ

في كل جدول يوجد عمود **الإجراءات** وفيه زر 🗑 (سلة مهملات). عند الضغط عليه تظهر رسالة:

> **تأكيد الحذف** — هل أنت متأكد من حذف فاتورة المبيعات SI-2026-00012؟
> سيتم حذف القيد المحاسبي المرتبط وتأثيره على الأرصدة، ولا يمكن التراجع عن هذه العملية.

لا يُحذف شيء قبل ضغط **تأكيد**، ثم تظهر رسالة «تم الحذف بنجاح».

ما يجب أن تعرفه قبل الحذف:

| الحالة | ما يحدث |
|---|---|
| فاتورة **مسددة أو مسدد جزء منها** | لن تُحذف. النظام يطلب منك حذف سند التحصيل/الدفع أولًا ويذكر رقمه |
| حذف سند تحصيل | يرجع رصيد الفاتورة كما كان وتعود حالتها «مرحّلة» |
| عميل أو مورد له فواتير أو سندات | لا يُحذف — أوقفه (تعطيل) بدلًا من الحذف |
| مستند داخل **فترة مالية مقفلة** | لا يُحذف — أعد فتح الفترة أو سجّل قيدًا عكسيًا |
| أصل تم إهلاكه / موظف في مسير رواتب / صنف مستخدم | لا يُحذف. استخدم الاستبعاد أو التعطيل |
| القيود الناتجة آليًا عن مستند | لا تُحذف من شاشة القيود — احذف المستند نفسه |

كل عملية حذف تُسجَّل في **سجل التدقيق** بلقطة كاملة للسجل قبل حذفه (من حذف، ومتى، وماذا كان داخل السجل)،
لذلك يمكن للمراجع تتبّع أي اختفاء في الأرصدة.

## 12. أسئلة متكررة

**«لماذا لا يظهر القيد في ميزان المراجعة؟»** لأنه مسودة أو قيد غير مرحّل — المرور بالمراجعة والترحيل مطلوب.

**«رسالة SOD_VIOLATION»** يحاول شخص اعتماد قيده/فاتورته بنفسه. اطلب من شخص آخر الصلاحية.

**«PERIOD_CLOSED»** الترحيل ممنوع على فترة مقفلة. راجع شاشة الفترات المالية.

**«لا أستطيع تصدير ملف»** صلاحية التصدير منفصلة عن صلاحية العرض؛ راجع مدير النظام.

**«هل الأرقام حقيقية؟»** نعم — كل بطاقة وتقرير محسوب من قاعدة البيانات. بيانات التطوير موسومة بوضوح.

## تعديل سجل / Editing a record

كل شاشة إضافة في النظام أصبح لها زر تعديل بجانب زر الحذف — في الجداول وفي صفحات
التفاصيل. التعديل متاح للمستخدم الذي يملك صلاحية `*.edit` (وهي ممنوحة تلقائيًا لكل
من يملك صلاحية الإضافة في نفس الشاشة).

1. اضغط أيقونة **القلم** في صف السجل أو في أعلى صفحة التفاصيل.
2. تُفتح نفس استمارة الإضافة لكن مملوءة بالقيم الحالية.
3. عدّل ما تريد ثم اضغط **حفظ التعديل**.
4. تظهر رسالة تأكيد: **«هل أنت متأكد من تعديل … ؟»** باسم السجل. لن يُحفظ شيء قبل
   موافقتك، ولو ألغيت تعود الاستمارة كما هي ببياناتك المكتوبة.
5. بعد الحفظ تُحدَّث القوائم تلقائيًا، ويُسجَّل التعديل في **سجل التدقيق** بالقيم
   قبل وبعد، واسم المستخدم، وعنوان الـIP، والوقت.

### ما يمكن تعديله ومتى

| الشاشة | متى يكون التعديل متاحًا |
|---|---|
| العملاء / الموردون | دائمًا — بشرط ألا يتعارض الكود مع سجل آخر |
| الأصناف والخدمات | دائمًا |
| الموظفون | دائمًا (قبل استخدام الراتب في مسيّر رواتب) |
| البنوك والصناديق | دائمًا |
| الحركات البنكية | قبل التسوية فقط — بعد التسوية تصبح مقفلة |
| الأصول الثابتة | قبل بدء الإهلاك — بعدها تُقفل التكلفة والعمر الإنتاجي |
| القيود اليدوية | في حالة **مسودة** فقط، وبعد الترحيل يجب العكس |
| فواتير البيع والشراء | في حالة **مسودة** فقط |
| سندات القبض والدفع | في حالة **مسودة** فقط |
| بنود الموازنة | دائمًا |

> **قاعدة ذهبية:** التعديل لا يُرحّل شيئًا ولا يعيد الترحيل. أي مستند مرحَّل يجب
> عكسه ثم إصداره من جديد — هكذا يبقى دفتر الأستاذ قابلًا للتدقيق.

### البنوك والصناديق

الصفحة صارت تعرض جدولًا كاملًا للحسابات البنكية والصناديق (الكود، الاسم، النوع،
حساب الأستاذ، العملة، الرصيد) مع **إضافة / تعديل / حذف** لكل حساب، إضافةً إلى جدول
الحركات البنكية. الحساب الذي عليه حركات أو سندات لا يُحذف — يُوقف بدلًا من حذفه.

### الموردون: التعديل والرصيد والدفعات

شاشة الموردين (وكذلك شاشة مديونية الموردين) بها زر **تعديل** يفتح لوحة المورد على تبويبين:

**١. بيانات المورد**
- الكود والاسم بالعربية مطلوبان، أما **الاسم بالإنجليزية فاختياري** — إن تركته فارغًا
  يُستخدم الاسم العربي تلقائيًا في كل الشاشات والفواتير.
- خانة **رصيد المستحق** تظهر داخل نموذج التعديل للقراءة فقط، وهي نفس الرصيد الظاهر في
  جدول الموردين، محسوب من فواتير المشتريات المرحّلة وغير المسدّدة بالكامل.
- الحفظ يطلب تأكيدًا: «هل أنت متأكد من تعديل المورد «…»؟»

**٢. الدفعات**
- إجمالي المستحق / إجمالي المدفوع / عدد الدفعات.
- جدول بكل دفعات هذا المورد مستقلًا عن غيره: **تاريخ الدفعة**، الرمز التعريفي، المبلغ،
  المخصّص للفواتير، غير المخصّص، الطريقة، المرجع، الحالة.
- جدول فواتير المشتريات الخاصة به مع المتبقي على كل فاتورة.
- زر **تسجيل دفعة**: تختار التاريخ والمبلغ وحساب البنك/الصندوق، وتحدد الفواتير التي
  تُخصَّص لها الدفعة، ثم «حفظ وترحيل». يتحدّث رصيد المستحق مباشرة ويظهر السند في
  شاشة المدفوعات ودفتر الأستاذ وسجل التدقيق.

### سندات القبض والدفع: نقدًا وتعديل وحذف

**طريقة الدفع:** في نموذج السند الجديد صار هناك حقل **طريقة الدفع**: «نقدًا» أو «تحويل بنكي» أو «شيك».
- اختيار **نقدًا** يوجّه السند تلقائيًا إلى **صندوق النقدية** (مثل «صندوق دمياط» — حساب 1111).
- اختيار التحويل أو الشيك يوجّهه إلى **الحساب البنكي** (حساب 1121 وما شابه).
- يمكن دائمًا تغيير الحساب يدويًا من قائمة «الحساب»، والقيد المحاسبي يتبع الحساب المختار.

**تعديل سند بعد إضافته:** من صفحة «المدفوعات والتحصيلات» أو من تبويب «الدفعات» داخل المورد — أيقونة القلم:
- التاريخ، المبلغ، طريقة الدفع، الصندوق/البنك، المرجع، الوصف.
- إذا كان السند **مرحّلًا** ولم تتغير إلا الملاحظات أو المرجع: يُحدَّث مباشرة.
- إذا تغيّر تاريخ أو مبلغ أو طريقة دفع السند المرحّل: يقوم النظام بـ **إلغاء الترحيل ثم إعادة الترحيل** بقيد واحد جديد مطابق للبيانات الجديدة، ويُسجَّل الحدثان في سجل التدقيق. لا يبقى أي قيد مزدوج.
- لا يمكن أن ينزل المبلغ عن قيمة المبالغ المخصّصة للفواتير — عدّل التخصيص أولًا.
- السند المُطابَق مع كشف بنكي لا يُعدَّل ولا يُحذف قبل **إلغاء التسوية** من صفحة البنوك (زر «إلغاء التسوية» على الحركة).

**حذف سند:** أيقونة سلة المهملات بجانب القلم — بعد تأكيد يحمل رقم السند. الحذف يعيد المبالغ إلى الفواتير ويحذف القيد المرتبط.

## المديونية وكشوف المقاولين / Debt & contractor statements

الوحدة الجديدة تحاكي **بيان مديونية المقاولين** الورقي الخاص بشركة شحن وتفريغ: لم
يعد الحساب مبنيًا على أصناف مخزنية، بل على **كمية × فئة وحدة** لكل مقاول أو مورد.

### 1. من أين تبدأ
القائمة الجانبية ← **المديونية وكشوف المقاولين**. الصفحة تعرض «حساب المديونية»
مجمّعًا في مجموعات:

| المجموعة | أمثلة من واقع الشركة |
|---|---|
| مقاول | الهندسية للتصميمات، الهندسية للهيدروليك، إبراهيم الحبشي (بالطن)، اللضام |
| عمالة | منتصر السيد، محمود السيد، منازع شافعي (ليلي)، السيد منتصر (نهاري) |
| معدات وإيجار | لودر محمد نجيب — إيجار شهري |
| نقل وحاويات | سيارات سي ترانس، مكتب القدس للحاويات |
| وقود | شراء سولار ومشتقات بترولية |
| ورش وصيانة | ورشة الصيانة |
| مشتريات متنوعة | أحمد تاج — مشتريات ومصروفات |

لكل حساب أربعة أرقام: **إجمالي المستحق**، **الدفعات المستلمة**، **رصيد افتتاحي**،
و**صافي المستحق** = افتتاحي + مستحق − مدفوع. كل الأرقام تُحسب على الخادم.

### 2. إضافة حساب مديونية
زر **«حساب مديونية جديد»** ← الاسم العربي (إلزامي)، الاسم الإنجليزي، **نوع الحساب**،
**وحدة الاحتساب** (طن / نقلة / حاوية / ساعة / إيجار شهري / بند)، الرصيد الافتتاحي،
حساب المصروف الذي تُقيَّد عليه التكلفة (افتراضيًا 5100 تكلفة المبيعات)، وربط
اختياري بمورد. الكود يُولَّد تلقائيًا (`DB-0001`…) إن تركته فارغًا.

### 3. كشف الحساب — سطر المستحق (البيان)
داخل الحساب، زر **«إضافة مستحق»**:

| الحقل | الشرح |
|---|---|
| التاريخ | تاريخ الاستحقاق |
| البيان | مثال: «تفريغ ذرة»، «حساب اللودر شهر يناير» |
| العملية | شحن / تفريغ / نقل / إيجار / مشتريات |
| الوحدة + الكمية + فئة الوحدة | مثال: **31,882.740 طن × 3 ج.م** = 95,648.22 ج.م |
| المبلغ (اختياري) | إذا تركته فارغًا يُحسب تلقائيًا = الكمية × الفئة |
| اسم المركب / العميل / المشحون | مثال: GREEN GENIE · ميدسوفت · ذرة |
| فترة الشحن ورقم بيان التشغيل | لتتبّع كل رحلة على حدة |

كل سطر مرحّل يُنشئ قيدًا: **مدين تكلفة الخدمة / دائن الموردون**. التعديل على سطر
مرحّل يُلغي القيد القديم ويُنشئ قيدًا جديدًا (لا يبقى قيد مزدوج)، والحذف يزيل
القيد معه.

### 4. السدادات — اذن صرف
زر **«إضافة سداد»**: المبلغ، التاريخ، **رقم اذن الصرف** الورقي، طريقة السداد
(نقدًا / تحويل بنكي / شيك)، الصندوق أو البنك، ومن قام بالصرف أو الاستلام. القيد:
**مدين الموردون / دائن الصندوق أو البنك**.

### 5. الطباعة والتصدير
من صفحة الحساب: **Excel** و**PDF** لكشف الحساب (مستحقات + سدادات + صافي المستحق)،
ومن صفحة الملخّص: تصدير «حساب المديونية» كاملًا بكل المجموعات وإجمالياتها.

### 6. الحذف والتعديل
كل سطر مستحق وكل سداد وكل حساب له زرّا **قلم** و**سلة** جانبًا بجانب الآخر.
الحذف يطلب تأكيدًا يذكر السجل (مثال: «هل أنت متأكد من حذف السداد 50,000.00 ج.م
باذن صرف 4412؟»). لا يُحذف حساب ما زالت عليه مستحقات أو سدادات حتى تُحذف أولًا.

### 7. الصلاحيات
`debt.view` (عرض) · `debt.create` (إضافة) · `debt.edit` (تعديل) · `debt.delete`
(حذف) · `debt.post` (ترحيل). المدير المالي ورئيس الحسابات يملكونها كاملة، المحاسب
يملك الإضافة والتعديل بلا حذف، والمراجع للعرض فقط — كل ذلك مفروضًا على الخادم.
